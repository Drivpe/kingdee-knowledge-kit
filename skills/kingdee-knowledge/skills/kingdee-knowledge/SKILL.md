# 金蝶知识库检索(kingdee-knowledge)——kd CLI 流程(v6.2 ask-first + 合成在调用方)

金蝶官方知识检索内核(`kd.core`,可 import 的库)的命令行入口 `kd`,
逆向自金蝶云社区公开后端,**纯匿名:零账号、零点数、无澄清、无对话限流**。
默认输出 JSON(stdout=数据,stderr=进度)。**库模式:无服务、无端口、无 HTTP、无本地落盘。**

v6 主轴是**彻底在线**(ADR-0005):模仿人类在论坛解决问题——用时在线搜、搜到即读即查。
ADR-0011 去服务化后,本地落盘缓存(landing / corpus / sqlite)与发版说明库预囤**整体取消**,
`kd ask` 一次调用即把该读的都带回来;**不存在任何本地语料可供 rg**。

v6.2 起**合成权在你手里**(ADR-0008):套件零模型依赖,只产资料包。拿到资料包后由**你**按
ANSWER-SPEC 合成;长资料包建议**开子代理**隔离上下文(见「合成与置信度」节)。

## kd 的定位(两级回退)

1. PATH 里的 `kd`(pipx 装到 `~/.local/bin`;Git Bash 下裸名走无扩展名 shim;cmd/PowerShell 走 kd.cmd)
2. 一键脚本兜底路径:Windows `%USERPROFILE%\.kingdee-kit\bin\kd.cmd`;
   Linux/macOS `~/.kingdee-kit/bin/kd`
3. 都没有 → 告知用户 `pipx install kingdee-knowledge-kit`,或运行本仓库安装器(install.ps1 / install.sh);
   **在此之前不要编造任何金蝶知识内容**

能力清单:`kd --help`(四条子命令与示例)与 `kd health`(内核版本/公开面/预算上限)

⚠️ **永远不要把 stderr 丢弃(禁 `2>/dev/null`)**:stdout=数据,stderr=进度与诊断;命令失败时先看
stderr/错误 JSON(带 hint),据此换调用方式,而不是静默改道 websearch。

## ⭐ 检索流程(三步,不要临场发挥)

### 第 1 步:kd ask——常规问题一律此入口

一站式资料包:内核内置**多路关键词拆解**(原句路+症状词路+字段/实体名词路+产品词路,≤7 路 RRF 融合,
规则在包内 `kd/query_routes.json`)→ 并行多路搜索 → 深读 topK 全文;
返回 `routes[]`(拆解明细)+ `sources[]`(每源 title/url/products/全文/chunks)+
`effectiveProductId`(本次实际生效的产品过滤)+ `budget{max,used}`。

```bash
kd ask "BOM分母27000 MRP运算变成平方" --topk 4
# --kw 可显式指定关键词(跳过自动拆解):kd ask --kw "BOM 分母" --kw "MRP 用量"
```

- **检索词改写由 ask 内置多路承担,你不再需要临场编词路**:直接把用户的症状描述原样交给 ask,
  内核负责跨越词汇鸿沟(如「分母变平方」↔文档命名的「生产单位数量」);
- **原句路**(ADR-0009):内核会把**完整问句**作为一路参与融合(保席位、相关性排序)。
  ⚠️ 上游对检索词有 **100 字符硬上限**,超限返回 `errorCode:409` 空壳 → 内核会**自动压到 100 字**,
  但被截掉的往往是问句后半段的关键症状词。**长问句请自己先提炼**:把最独特的症状/字段/报错词
  放在**前 100 字内**(如「分母显示27000 MRP运算变成27000平方」),比丢整段更有效;
- 返回体里看 `routes[]` 理解内核拆了哪些路;`budget_exhausted:true` 表示上游预算耗尽,
  先消化已获资料,不要立刻重跑;
- sources 展示排序 answer 优先(症状近似度最高),knowledge 紧随(补根因解释)——两类都要看;
- `synthesisBrief`(见下节)是**召回信号摘要**,先读它再决定要不要合成。

### 第 1.5 步:合成与置信度(你的职责,不是 kd 的)

**kd 不合成回答**(ADR-0008,零模型依赖)。拿到资料包后**由你合成**,并给出召回置信度判定。

**为什么开子代理**:资料包含 topK 全文,动辄 2 万字塞进主对话会挤掉上下文。
把「资料包 + 合成规范」交给子代理,它只回「答案 + 结构化引用」。

⚠️ **子代理看不到你当前对话**,harness 给它的系统提示词是通用 agent 提示,**不含本技能的任何规范**。
所以下面模板里的规范必须**原样传给子代理**,不能假定它自己知道。

**判定档位**(ADR-0010,三档枚举,**不要用数值分数**——LLM 自报概率无校准、
与 `topScores` 不同量纲、且分数诱导过度自信):

| 档位 | 判据 |
|---|---|
| `answerable` | 召回文档中有段落直接说明了机制/字段/步骤 |
| `partial` | 有相关材料,但未覆盖用户问的那个点 |
| `uncovered` | 召回内容与问题不匹配,或检索本身未命中 |

**子代理提示词模板**(照抄,填入资料包):

```text
你是金蝶 ERP 知识回答合成员。仅依据下面提供的资料作答,不编造。

## 回答格式(强制)
结构化 Markdown 三段式:
1. `## 问题原因分析` —— 机制/字段/流程层面的原因;
2. `## 解决方案` —— 编号步骤(### 第一步/第二步…),每步给可直接执行的菜单路径/字段名/参数值;
3. `## 操作边界` —— 适用版本/前提/不覆盖的情况。
并列信息用 Markdown 表格;正文关键结论后标 `[n]`,文末 `## 参考来源` 列 `[n] 标题 —— 类型`
(类型取实体 type:官方文档/社区问答/社区文章)。

## 引用规则(硬)
- answer(社区问答)引用**只用于症状对齐**;根因解释**必须**引 knowledge 的根因段落,
  只引 answer 不算根因可解释;
- **「官方已修复」类问题优先引官方发版说明的「模块-问题-修复」条目**;社区说法与官方说明冲突时,
  **以官方说明为准**。⚠️ 本套件**没有**本地发版说明库(随去服务化取消)——
  这类问题靠 `kd ask` 召回 + 站外搜索 `site:vip.kingdee.com 发版说明 <关键词>`(见「第 2 步」),
  查不到就按「现有资料未覆盖」如实声明,**不要凭印象断言某版本修复了某问题**。
- **区分权威级**:官方文档确认的结论**直接陈述**;社区问答/文章得出的标注「**来自社区经验**」。
  不要把社区推测写成官方口径,也不要把官方结论降格成"据说"。
- 资料源带 `chunks`(形如 `[chunk#2 【操作步骤】]`)时**优先依据命中段落**,
  不引与结论无关的全文;
- **产品线核对(单点核对 `effectiveProductId`)**:引用前核对资料包顶层 `effectiveProductId`
  是否等于本次预期的产品线 ID(93 旗舰版 / 87 苍穹 / 1 企业版标准版)。
  **它为 `null` 表示本次未带任何产品过滤**——此时不得当作某条产品线的答案引用,
  正文须标注「本次检索未按产品线筛选」。
  ⚠️ `sources[].products` 装的是上游中文类目名(`["金蝶AI套件"]`),与整数 ID **值域不可比**,
  只能当阅读提示,**不得**拿来判定"产品线不符故排除该源"。
- 网页 URL 匿名不可访问(vip.kingdee.com 一律 302 登录墙),**不要把它当作可点依据**。

## 产品线粘性(硬规则,2026-09-06 旗舰版串线事故条款)
> 事故:agent 回答「金蝶旗舰版 BOM 维护」时,中途把 `--product 93`(旗舰版过滤)变道为
> `--product 0`(不过滤),召回了星空企业版内容(ENG_BOM/T_ENG_BOM)且未甄别,
> 把企业版答案当成旗舰版输出(正确答案:旗舰版是 pdm_mftbom)。以下两条无例外。

1. **产品路由粘性**:同一问题会话内,首次 `kd ask` 确定的 product 路由
   (`--product 93` 旗舰版 / `1` 星空企业版 / `87` 苍穹)**必须贯穿该会话后续所有检索调用**。
   **禁止中途变道 `--product 0`(不过滤)、禁止改用其他产品线过滤、禁止不带 --product 重新检索**。
   若资料中出现了新的产品线线索(如明确提到另一产品),**必须先向用户确认后再切换**,
   不得自行判断、不得静默切换。
2. **单点核对 `effectiveProductId`**:引用与合成前核对资料包顶层 `effectiveProductId`
   是否等于本次预期产品线 ID(93/87/1)。**它为 `null` 即本次未带产品过滤**——
   不得当作某条产品线答案引用,须在正文标注「本次检索未按产品线筛选,可能混入其他产品线内容」。
   ⚠️ `sources[].products` 是上游中文类目名(如 `["金蝶AI套件"]`),与 `effectiveProductId`
   的整数 **值域不可比**,全无可执行相等判断——**只能作阅读提示,不得作为排除某源的判据**。
   排除异产品线内容靠 `effectiveProductId` 与正文内容核对。
3. **过滤回显不符即停**:`effectiveProductId` 与预期不符(如要旗舰版 93 却回显 `null`)时,
   **必须停止合成并向用户报告**,禁止带着错误过滤继续作答。

## 置信度判定(必填)
先输出一行 JSON 头,再写正文:
{"confidence":"answerable|partial|uncovered","basis":"一句话依据"}
- `answerable`:召回资料有段落直接说明了机制/字段/步骤;
- `partial`:有相关材料,但没覆盖用户问的那个点;
- `uncovered`:召回内容与问题不匹配,或检索没命中。
**不要用数值分数。** 当判定为 `partial`/`uncovered` 时,正文必须明确写出
「现有资料未覆盖…」并说明缺什么,**不要硬凑步骤**。

## 召回信号(供你判定,来自 kd 的客观数据)
{把资料包的 synthesisBrief 原样粘这里:
 sourceCount / topScores / routeKinds / budgetExhausted / upstreamUsed / recallHint}
- `budgetExhausted:true` ⇒ 本轮检索不完整,判定应更保守;
- `routeKinds` 只有 `product` 而无症状路/实体路命中 ⇒ 片段路全空,很可能 `partial`/`uncovered`。

## 资料包
{把资料包的 sources 原样粘这里:每源的 type/title/id/products/chunks 或全文}
```

**返回给主对话**:完整答案正文 + 结构化引用清单(`n/title/type/entityId`),以及那个 `confidence` 头。

### 第 2 步:在线兜底——ask 空手或解释不了根因时,站外搜索

`kd ask` 的 sources 空手、或拿到的资料解释不了根因时,才动用 websearch:

```bash
# 站外兜底,回答必须标注「站外语源」
site:vip.kingdee.com 发版说明 <修复项关键词>
site:help.open.kingdee.com <功能名词>
```

诚实边界:部分发版说明不在搜索索引内,搜不到≠不存在;不要因为第三跳也无果就断言「官方没有」,
按 ANSWER-SPEC 写「现有资料未覆盖」。

## 手动细粒度调试命令(search/read)

仅当需要精确控制(分页/类型过滤/指定单条深读)时手动使用,常规问题不要从 search 起步:

```bash
kd search "信用额度控制" --product 93 --size 10
# → {"total","results":[{type,id,questionId?,title,snippet,adopted?,url,…}]}
# --type knowledge|answer|article 可过滤;knowledge=官方文档(权威优先)
# --product 93=星空旗舰版(默认)、87=苍穹、1=星空企业版/标准版、0=不过滤
# ⚠️ --product 必须沿用本会话首次 ask 确定的路由,禁止变道 0(硬规则见下节)

kd read <id>                          # type=knowledge → 官方文档全文
kd read <questionId> --kind answer    # type=answer → 问题+全部回答+追问链
kd read <id> --kind article           # type=article → 社区文章全文
# --kind 照抄 search 结果的 type 字段,零翻译
```

## 回答规范

遵循 `docs/ANSWER-SPEC.md`(单一事实源):结构化 Markdown(原因分析→编号步骤→操作边界)、
表格、`[n]` 编号引用(可细到 `[n](chunk#m)`)、**根因引用规则**(answer 引用用于症状对齐,
根因解释必须引 knowledge 的根因段落;官方发版说明需站外取原文)、资料未覆盖就诚实声明,**不编造菜单路径/字段名/接口名**;
社区内容标注「来自社区经验」;引用一律用资料包 sources 里的原始 url。

## 快捷方式

- `kd ask "问题" --topk 4` —— **唯一常规入口**:原句路+多路关键词拆解+深读 topK 全文+`synthesisBrief` 一次带回
- 拿到资料包后**开子代理合成**(规范模板见「第 1.5 步」),返回答案 + 引用 + `confidence` 三档
- `kd health` —— 内核自检(库模式:确认公开面与路由规则已加载,排查环境问题先跑它)
- `kd search` / `kd read` —— 手动细粒度调试命令(常规问题不用)

## 内核或上游异常时

```bash
kd health --help   # 先看用法
kd health          # 正常时回 JSON 自检报告;失败时错误 JSON 的 hint 字段带修复指引
```

仍不行才回退 websearch/webfetch(`site:vip.kingdee.com`、help.open.kingdee.com),并告知用户。

## 禁止事项

- **同一问题会话内禁止把 --product 从已确定的路由变道为 0(不过滤)或其他产品线**;
  产品线切换必须先经用户确认(见「产品线粘性」硬规则)
- **禁止把 `sources[].products` 的中文类目名当作产品线判据**(值域不可比);
  `effectiveProductId` 与预期不符时必须停下报告,禁止带着错误过滤继续作答(见「产品线粘性」硬规则)
- 不要编造端点/字段/参数;内容一律以 kd 返回的 JSON 为准
- 常规问题不要从手动 search/read 起步——一律先 kd ask;也不要在 ask 之外临场编检索词路(多路已内置)
- 不要把检索失败当成"官方没有相关文档"——先走完三步流程,再按「现有资料未覆盖」诚实声明
- 不要高频连续检索(保持人类频率;本地无缓存可复用,每次 ask 都真实消耗上游)
- 不要尝试官方 /aisapi/ai-search 管线——需登录+身份认证,匿名只会得到「未授权操作」
