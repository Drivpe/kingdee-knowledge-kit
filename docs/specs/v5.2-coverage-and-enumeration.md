# Spec:v5.2 全量快照覆盖度估计与枚举效率升级

> 产出自 2026-09-06 会话(corpus 全量快照首轮运行期间,基于调研
> `docs/research/2026-09-06-coverage-estimation-and-enumeration.md`,论文脉络:hidden web siphoning /
> Chao1 覆盖估计 / tail-focused query selection)。issue #1 的后续,不阻塞其收尾。
> 术语遵循 CONTEXT.md(corpus 语料目录/发现层/全量快照);决策依据见 docs/adr/0004 及其增补。

## Problem Statement

全量快照靠 163 个关键词逐页枚举,但存在三个结构性盲区:①**不知道还剩多少没抓到**——词与词的并集永远无法数学完备,当前只能凭"每页还有新文档"的体感判断何时停;②**词表是一次性的**——"标题高频名词"只在写词表时用了一次,新抓的几万篇文档没有反哺词表;③**每词 2,500 条的钳制浪费深水区**——时间倒序下单词超过 2,500 条的部分永远抓不到,而时间窗明明是可以切的维度;④词表尾部的窄词收益趋零时仍会白白跑满请求预算。

## Solution

四条升级,全部沿用现有发现层设施与红线框架,不改变"上游被请求,语料才更新"的不变量:

1. **覆盖度仪表(先做,零上游成本)**:fullscan 逐词记录"命中了哪些文档",跑完即可用生态学估计器算出「估计总量 N̂(Chao1)与样本覆盖率 Ĉ」,把"还要不要扩词表/何时停"从体感变成数字。
2. **滚动提词闭环(snowball)**:每轮抓完后从新增文档标题再提取高频词,与"上轮每页新增文档数"(边际增益)排序合并进候选词池,下一轮优先跑高增益词;LLM 仅作候选池枯竭时的扩词器(不引入在线依赖)。
3. **时间窗分区**:利用 sortsType=2 时间倒序特性,对已触顶 2,500 条的宽词按年份切片重抓,每窗独立享有 50 页额度——专收宽词深水区的老文档。
4. **饱和即停**:新词的边际增益(每请求新增文档数)连续低于阈值时跳过/收工,词表尾部不再空耗预算。

## User Stories

1. 作为用户,我想在 fullscan 结束时看到"估计已覆盖 N̂ 的 X%",所以我不用猜语料够不够全。
2. 作为用户,我想让"词表"随抓取自动生长,所以冷门域文档不会因为初始词表没覆盖而永远缺席。
3. 作为用户,我希望宽词超过 2,500 条的老文档也能被收进来,所以时间倒序钳制不再吃掉深水区。
4. 作为维护者,我想让边际增益趋零的词自动跳过,所以 7,500 请求的预算花在刀刃上。
5. 作为维护者,我想用现有抓取日志直接算 Chao1,所以估计覆盖度不需要任何额外上游请求。
6. 作为维护者,我想用假服务回归 snowball 的提词与调度逻辑,所以升级不依赖打真上游。
7. 作为 agent,我想在 SKILL 里看到"何时该重跑 fullscan"的判据(覆盖率跌破阈值/增量饱和),所以重跑决策有依据。
8. 作为用户,时间窗分区抓回的老文档与现行 stub 规范一致(原链接/front-matter/幂等),所以下游(rg、写穿)零适配。

## Implementation Decisions

- **覆盖度数据结构**:fullscan 进度文件在 (type,id) 集合之外,增记「词→命中文档集」的倒排映射(词级抓取结果),供 f1/f2 统计;文件体积可控(词×文档 id),仍走断点续跑文件同一处。
- **估计器**:Chao1(N̂=D+f1²/2f2)与样本覆盖(Ĉ=1−f1/n)为主;实现为离线小工具,输入进度文件、输出估计值与置信区间;词间相关性导致的保守偏差在输出中显式标注;如需外推曲线可引入 iNEXT 方法,但不引 R 运行时依赖(必要时 Python 复现算法)。
- **snowball 闭环**:提词器复用本轮"标题高频名词"的思路,阈值化(出现 ≥k 次才入候选);候选词池 = 初始词表 + 历史滚动词,按边际增益排序;每轮跑完后把新词追加进词表文件(带来源标记)。
- **时间窗分区**:仅对"触顶 2,500 条"的词启用;切片粒度按年(sortsType=2 时间倒序下逐窗下钻);是否值得分区由该词的 totalElements 与 2,500 的比值决定(≥2 倍才切)。
- **饱和判据**:某词连续 N 页新增为 0 即收词(现状已有);新增"某词前 P 页边际增益 < 阈值即跳过",阈值默认沿用 Crawl4AI 式设计(具体数值在实现时用首轮真实数据校准,写进 ADR)。
- **红线不变**:1 请求/秒;增量轮 ≤200 请求;全量重跑需用户重新豁免;时间窗分区本身不增加新请求类型,只是同一预算下的再分配。
- **范围不变**:仍限星空旗舰版(93)+苍穹(87);全站放宽与 school/帮助中心通道不在本 spec(issue #2、交接文档 18)。

## Testing Decisions

- 唯一测试缝仍是**本地 HTTP 服务 API**(verify_ksearch 既有方式),snowball/时间窗/饱和逻辑对假 /search 服务回归(沿用 v5 fullscan 幂等检查的假服务模式);
- 估计器用**合成数据做确定性单测**(构造已知 f1/f2 分布验证 Chao1 数值与区间),不依赖真服务;
- 覆盖度输出进 fullscan 收尾 JSON 与覆盖率报告(对齐 docs/discovery-report-v5.md 体例),验收时人工核对量级合理性;
- 先标金后测管线原则延续:估计器的"金标"=首轮真实抓取日志(词→文档倒排),升级前后重算对比。

## Out of Scope

- 放宽产品范围至全站(需另行红线豁免拍板)
- school 子系统 / 帮助中心通道(issue #2、交接文档 18)
- 登录态任何通道;正文预抓;常驻定时
- 在线检索管线(/search /ask)的任何改动——本 spec 只动发现层脚本与其进度文件

## Further Notes

- 依据论文:Ntoulas et al. JCDL 2005(siphoning)、Madhavan et al. VLDB 2008(收益衰减即停)、He et al. WSDM 2013(tail-focused)、Lawrence & Giles Nature 1999(重叠率估计);完整清单与链接见调研报告。
- 实施顺序建议:覆盖度仪表 → 饱和即停 → snowball → 时间窗分区(前两个立即可用,后两个依赖首轮真实数据校准)。
