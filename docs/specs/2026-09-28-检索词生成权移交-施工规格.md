### A4. 超限行为(写在返回体里,不静默)

```
N = 7   (配置值,实测:7 词 = 7 次请求 = 3.33 秒)
```

- 返回体**必须写明丢了几条**:新增 `keywordsDropped`(整数,0 表示没丢);

  违规的是**不说**。这条是既有纪律(`clamp_query` 的"宁可报错也不静默截断")在多路场景的落地。

## File B　输出面:字段集与错误类型(File A 完成后开始)

### B1. 字段集按类型分三份(实测可达性)

```jsonc
"search": {
  "resultKeysCommon": ["type", "id", "title", "url", "snippet", "products", "hitRoutes", "routes"],
  "resultKeysByType": {
    "knowledge": [],
    "question":  ["adopted", "answersCount", "comments", "questionBody"],
    "article":   ["comments", "supports"]
  },
  "note": "按实测可达性分档。公共部分在前,类型专属在后。"
}
```

**取值规则**:类型不适用的键**直接不出现在该条目上**(而非填 `null`)。
理由:「结构性不适用」(知识文档永远没有回答数)与「上游没给值」是两件事,
混成 `null` 会让调用方分不清。`comments` 三类都可达(含公共部分亦可,建议放公共)。

⚠️ **`_manifest_project` 要改**:现在 `{k: n.get(k) for k in result_keys()}` 会把缺失键统一填 `None`,
必须改为"按该条目的 `type` 取对应的键集,缺键不产出"。

### B2. 修两处真实缺陷

| # | 缺陷 | 位置 | 修法 |
|---|---|---|---|
| **D1** | `adopted` 在 article/knowledge 条目上被合成假 `False` | `_manifest.py:165` 的 `out["adopted"] = bool(...) or bool(...)`,在 `for n in ns[1:]` 里**同 key ≥2 条就无条件执行**,把缺失键的 `None` 折成 `False` | 改为"只在任一侧**有值**时取或";B1 之后 article 的 `adopted` 根本不该出现,这条顺带解决。⚠️ 它已导致 `tests:2085` 的在线断言("非问答条目 adopted 应为 None")在真实数据上会红,只因合成数据 id 互异而不触发合并 |

   - 声明里删一个顶层键 → 真实输出跟着少(证明 `topKeys` 有消费者);
   - 给 9 个词 → `keywordsDropped=2`(证明显式通报生效);
   - 人为让内核重新生成检索词 → `t_no_decomposer_symbols` 变红(证明禁止清单有抓取力);
4. 技能安装同步:`md5sum` 仓库版与 `~/.agents/skills/kingdee-knowledge/SKILL.md` **必须相同**;
5. **不做 `git commit`**——按既有约定由用户本人处理。
