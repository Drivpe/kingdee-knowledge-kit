## 0. 结论摘要

三条硬结论，其中**两条与既有文档不一致**：

1. **`knowledge/<id>` 可贴**：30/30 首跳 200、最终 URL 原地不变、`meta 知识详情` 非空。与既有口径一致。
   ⚠️ **但并非永久有效**——本稿自身即找到反例 `knowledge/402990431979506944`（稳定 302，Lead 复现已确认）。
2. **`article/<id>` 可贴，且 12/12 均「200 + 最终 URL 原地不变」**：既不存在「302 登录墙」，也不存在「302 到 `knowledge/<新id>` 的路径迁移」。
   **这推翻了 ADR-0012 与 `_impl/_upstream.py` 注释中的「article → 302 → knowledge（路径迁移）」表述。**
   ⚠️ 同样非永久有效：反例 `article/248777993676668672`（稳定 302，Lead 复现已确认）。
3. ~~**`question/<id>` 的 302 成因不是「帖子被删」**…… 复数路径 `questions/<id>` 37/38 可贴（97.4%）。~~
   ⚠️ **本条已被 Lead 于 2026-09-27 复核证伪，整条作废**：复数路径不存在（15/15 全 302，
   站点自身 `/questions` 列表页亦 302）。**保留的有效部分**：`question/<id>`（单数）恒 302 → `/error/404`，
   故引用 `answer` 条目时**不给该路径链接**。至于「帖子是否被删」——上游 `/api/questions/{id}`
   仍返回完整 JSON 这一点**未被推翻**，但**页面路由不可达是既成事实**，成因表述对引用决策无影响。

## 1. 判定方法

### 1.1 口径

**必须看最终 URL（`url_effective`），状态码 200 不足以判定可用。**
判定顺序：跟随重定向 → 比最终 URL → 再验正文，而不是读首跳状态码。

### 1.2 `question/` 的 302→200→`/error/404` 陷阱（原始证据行）

```
$ python3 probe2.py   # urllib 禁用自动重定向（自定义 NoRedirect handler），逐跳记录
{"i": 4, "kind": "answer", "id": "690211958565676032", "first": 302, "loc": "/error/404",
 "final": 200, "final_url": "https://vip.kingdee.com/error/404", "bytes": 399544,
 "err": true, "vtLen": 221, "metaLen": 0, "needle": false}
```

```
$ curl -sk -A "$UA" -o /dev/null -w "code=%{http_code} redirect=%{redirect_url}\n" \
    "https://vip.kingdee.com/question/690211958565676032"
code=302 redirect=https://vip.kingdee.com/error/404

$ curl -skL -A "$UA" -o /dev/null \
    -w "final_code=%{http_code} nhops=%{num_redirects} url_effective=%{url_effective} size=%{size_download}\n" \
    "https://vip.kingdee.com/question/690211958565676032"
final_code=200 nhops=1 url_effective=https://vip.kingdee.com/error/404 size=399544
```

**陷阱点**：跟随重定向后**最终状态码是 200**，只看状态码会把已失效的链接误判为可点。必须看 `url_effective`。

全量复核：38/38 条 `question/<id>` 全部「首跳 302 → 最终 URL `/error/404`」，且 `/error/404` 解压后恒为 **399544** 字节（正是同一张 404 页）：

```
$ python3 -c "... 统计 ..."
=== question/ 单数 n=38 ===
首跳码 Counter({302: 38})
最终码 Counter({200: 38})
最终URL分布 Counter({'https://vip.kingdee.com/error/404': 38})
```

### 1.4 重要方法学纠正：必须显式解压 `Content-Encoding: gzip`

该站对同一 URL 的响应**压缩态与解压态字节数相差约 6 倍**，且 `Content-Encoding` 头有时缺失标注。**误把压缩态字节当正文长度会得出错误结论**（本人第一版脚本就踩了这个坑，得到 8 万字节的假值）：

```
$ python3 -c "... 记录响应头 ..."
status 200 raw bytes 91995
headers: {'Content-Type': 'text/html; charset=utf-8', 'Content-Encoding': 'gzip', 'Server': 'CW', 'Vary': 'Accept-Encoding'}
  gzip decompressed -> 554906
```

**本文所有「正文字节」均指解压后字节。** `/error/404` 各形态换算：

```
$ python3 -c "... 精确测量 ..."
https://vip.kingdee.com/error/404 => status=200 压缩态字节=64482 解压后字节=399544 CE=gzip
https://vip.kingdee.com/error/404?lang=en-US => status=200 压缩态字节=64482 解压后字节=399544 CE=gzip
```

### 1.5 另一个会让结论全错的方法学坑：`urllib` 默认跟随重定向

`urllib.request.urlopen` **默认自动跟随 302**，因此 `resp.status` 拿到的是**最终码**而非**首跳码**。若用它直接读 `status`，会把 `question/` 的首跳 302 全部记成 200，从而得出「`question/` 可点」的**反向错误结论**。
必须挂 `HTTPRedirectHandler` 子类、让 `redirect_request` 返回 `None` 来禁用自动跟随，才能取到真实首跳码（本文件 §1.2 的证据行即用此法）。这个坑在本人首轮脚本中真实发生过，故在此显式记录。

### 1.6 ⚠️【已作废】「复数 `questions/` 是真实内容路由」的对照实验

> **本节结论已被 Lead 于 2026-09-27 复核证伪，整节作废**，保留原文仅为追溯错误来源。
> 复测结果：15/15 复数路径样本全部 302 → `/error/404?lang=en-US`，且**站点自身的 `/questions`
> 列表页亦 302**——复数路由不存在。下方「臆造 id → 302、真实 id → 200」的对照实验**不可复现**
> （真实 id 与臆造 id 同样 302）。请勿据此节给 `answer` 条目生成 `questions/` 链接。
> 裁定依据见文首「复核裁定」节。

用**臆造 id** 排除「兜底页」假设：

```
$ for id in 999999999999999999 1 123456; do curl -sk --compressed -A "$UA" \
    -o /dev/null -w "%{http_code}|%{redirect_url}\n" "https://vip.kingdee.com/questions/$id"; sleep 2; done
  questions/999999999999999999   302|https://vip.kingdee.com/error/404?lang=en-US
  questions/1                    302|https://vip.kingdee.com/error/404?lang=en-US
  questions/123456               302|https://vip.kingdee.com/error/404?lang=en-US
```

臆造 id → 302；真实 id → 200 且含正文。故 `questions/<id>` 是**按内容存在与否作答的真实路由**，不是兜底页。
