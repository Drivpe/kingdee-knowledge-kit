# 问答帖链接形式实测(2026-09-29,匿名侧)—— 纠正 09-28 复测的 `question/` 结论

> **执行者**:本轮 Lead(独立完成)
> **上游**:`https://vip.kingdee.com`(匿名、零 cookie、零账号,与内核同链路)
> **纪律**:仅 HTTP GET 读取;**长/短形式各 10 次、间隔 3 s、无并发**;未写任何上游数据。
> **判定口径**:**跟随重定向看最终 URL(`url_effective`)**。落到 `/error/404` 判死,其余判活。
> **关联**:`docs/research/2026-09-28-链接可点性复测.md`(**本文件纠正其 §4 的 `question/` 行**)

## 0. 一句话

**问答帖链接是可点的,失效的不是"问答这一档",是 URL 形式。**
正确形式 = `https://vip.kingdee.com/questions/<帖子号>/answers/<回答号>`(多个/复数/带回答号),
实测 **22/22 可点**。内核当前拼的 `https://vip.kingdee.com/question/<帖子号>`
(单数/无回答号)实测 **22/22 不可点**。

因 `contract.json` 的 `linkPolicy` 对 `question` 是 `no-link`,这一整档**当前不给链接**。
该政策建立在此前"问答恒不可点"的结论上,**那个结论现在被推翻**。

## 1. 决定性对照实验

同一帖子、两种形式各测 10 次,间隔 3 s:

| URL 形式 | 活 | 死 |
|---|---|---|
| `/questions/<qid>/answers/<aid>`(正确) | **10** | 0 |
| `/question/<qid>`(内核现用) | 0 | **10** |

补测两个帖子各 6 次(样本 `756242644560174080` / `532937350112921856`):

| URL 形式 | 活 | 死 |
|---|---|---|
| 长形式(正确) | **12** | 0 |
| 短形式(现用) | 0 | **12** |

**合计:长形式 22 活 0 死,短形式 0 活 22 死。** 样本帖子号来自内核 `kd search` 真实产出,非人工挑选。

### 页面内容核实(不只是状态码)

长形式页面 `<title>` 与上游 `question.title` **逐字一致**,页面正文含帖子标题与采纳回答原文:

```
URL      : https://vip.kingdee.com/questions/782288611831176448/answers/782288611965394176
最终 URL  : 原地不变(无重定向)
title    : 资产折旧单生成凭证报错没生成一条凭证分录,且生成凭证没反应怎么办?
正文字节  : 474321 B
含帖子标题 : 命中
含采纳回答 : 命中(「分录筛选条件用折旧明细页签的字段即可生成凭证。」)
```

对照短形式:最终 URL 落 `/error/404`,页面 `<title>` 是站点通用标题,不含帖子内容。

### 回答号必须精确(不是通配)

```
aid=782288611965394176  (真实) → 200,原地,title 正确
aid=782288611965394177         → /error/404
aid=1                          → /error/404
aid=0                          → /error/404
```

即站点对 `answers/<aid>` 做**精确校验**,"随便填一个也能开"不成立。

## 2. 一个必须留证的观测方法陷阱(第四次)

本文件的过程里,同一 URL 曾**一次测出可点、随后 10 次全不可点**。当时的推断是
"站点按请求头降级"(因为补上 `Referer` / `Accept-Language` / `Accept` 后那次通过)。
**该推断已证伪**——变量逐一隔离后:

| 请求头 | 结果 |
|---|---|
| 裸(无额外头) | 活 |
| 仅 `Referer` | 死 |
| 仅 `Accept-Language` | 死 |
| 仅 `Accept` | 死 |
| 仅 UA(Chrome 120) | 死 |
| 三头齐全 | 死 |

**规则不存在:同一 URL 时活时死,与请求头无关。** 那是**限流放行窗口**——
正是 09-28 那份文档 §2.1 已经记过的同一个陷阱(该文档把它归因为"限流期被读成常态")。

**判定口径至此累计四个坑**(前三个已在前两份文档记录):

1. 只看首跳状态码 → 会把**失效判成可点**(`question/` 最终状态码恰为 200)
2. 只看首跳状态码 → 会把**可点判成失效**(`article/248777993676668672` 首跳 302,实际迁移成功)
3. 单次观测不排除限流 → 会把**限流期表现推广成路径级常量**
4. **误把偶发的一次通过归因成"请求头差异"** → 会得出一个不存在的规则(本文件新增)

**留证**:任何"某路径可点/不可点"的结论,**必须多轮次重复且各形式对照**,
单次或少量观测不足以定性。本文件的 22/10/10 次对照即为该纪律的执行。

## 3. 被证伪的一条外部结论

同一轮调查中,一个子代理报告称「`/questions/<帖子号>`(复数、不带 `answers` 段)
带任意 UA 均 200 且渲染真实标题」,并指出这与 `contract.json` 的
「复数路径同样不存在(15/15 全 302)」冲突,建议复核该 forbidden 备注。

**复核结果:该结论不成立。** 4 个真实帖子号测 `/questions/<qid>`(复数、无 `answers` 段),
**4/4 落 `/error/404`**。该子代理看到的应是 404 页本身返回 200 这一假象(陷阱 1),
且其样本仅 1 条。

**`contract.json` 的 forbidden 备注「不要把 `question/` 改写成 `questions/`」仍然有效**,
但**其理由需要修正**:复数路径并非"不存在",而是**复数路径必须带 `answers/<aid>` 段**。
即两者都错,但错法不同:

| 形式 | 判定 | 真实原因 |
|---|---|---|
| `/question/<qid>`(单数) | 死 | 该路径整体不存在 |
| `/questions/<qid>`(复数、无 aid) | 死 | 路径存在但**缺必需的回答号段** |
| `/questions/<qid>/answers/<aid>`(复数、带 aid) | **活** | 正确形式 |

## 4. 与站点自身行为的一致性

站点列表页(`https://vip.kingdee.com/questions`)自身链出的就是长形式——
即**人类从页面点击必然可打开**,这与用户"点进去就能看到回答"的直觉一致。
本轮所有样本的 URL 均可用 `curl -sSL -A '<UA>'` 匿名复现,无需登录态。

## 5. 复现

```bash
Q=782288611831176448      # 帖子号(来自 kd search 的 question 条目 id)
A=782288611965394176      # 回答号(该帖采纳回答的回答 id,上游 question.bestAnswer[0].id)

# 正确形式:应 200 且最终 URL 原地不变
curl -sS -o /dev/null -w '%{http_code} %{url_effective}\n' -L --max-time 25 \
  "https://vip.kingdee.com/questions/$Q/answers/$A"

# 内核现用形式:落 /error/404
curl -sS -o /dev/null -w '%{http_code} %{url_effective}\n' -L --max-time 25 \
  "https://vip.kingdee.com/question/$Q"

# 判活必须看最终 URL,不能看状态码(两者都是 200)
```

**上游回答号的取法**(内核需要的数据源,两条路都有):

```python
# 路一:从 search 的 answer 条目直接取(原始 JSON 里两个 id 都在)
#   x["questionId"] → 帖子号
#   x["id"]         → 回答号  ← 内核当前只取前者,这个被丢弃
# 路二:从 read 的详情端点取
#   GET /api/questions/<帖子号> → d["bestAnswer"][0]["id"] = 采纳回答的回答号
#   (d["answers"] 是回答**条数**,不是数组;不可当数组遍历)
```

## 6. 结论与政策影响

| 项 | 结论 |
|---|---|
| 问答帖可点性 | **可点**(长形式 22/22) |
| 正确 URL 形式 | `/questions/<帖子号>/answers/<回答号>` |
| 内核当前形式 | `/question/<帖子号>` —— 恒不可点 |
| 回答号来源 | `_upstream._norm_item` 的 answer 分支原本就拿得到(`x["id"]`),当前未取 |
| 帖级合并时的取舍 | 采纳回答优先(`isAdopt`),无采纳回落上游首条 |
| 对 `linkPolicy` 的影响 | `question: "no-link"` 的依据(匿名 9/9 + 登录态 1 条不可点)**已被推翻**,
  该行需重新裁定——**但本轮只记录事实,不改政策** |

⚠️ **不改政策的理由**:`linkPolicy` 是 `contract.json` 里的契约字段,改它属于对外行为变更,
须与"清单条目补回答号"的代码改动一起做(否则会给出"政策允许但内核给不出链接"的空承诺)。
本轮为纯文档轮,故只把事实与 URL 形式固化在此,代码与政策一并留给下一轮。

⚠️ **遗留未测**:带回答号的长形式在**登录态**下的行为未测(本文件全部为匿名侧)。
按 09-28 文档已记录的方向("匿名判定会对登录态用户产生假阴性"),
匿名可点不影响登录态结论;但反向(匿名可点、登录态不可点)本轮**未测**,不应排除。
