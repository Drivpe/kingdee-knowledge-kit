# 额外 entity-type 的链接形式复验(2026-09-29)

> **执行者**:本轮 Lead(独立完成)
> **上游**:`https://vip.kingdee.com`(匿名、零 cookie、零账号,与内核同链路)
> **纪律**:仅 GET;每请求间隔 ≥1.05 s;无并发;未写任何上游数据
> **判定口径**:`url_effective`(= 跟随重定向后的最终 URL),落 `/error/404` 判死;
>   状态码**只作辅证**——本仓已累计四次误判,全部源于"只看首跳状态码"
> **关联**:`docs/research/2026-09-29-上游entity-type全集与静默丢弃.md`(其 §5 的
>   `LearningCourse` 行**被本文件推翻**)、`docs/research/2026-09-29-问答帖链接形式实测.md` §2

## 0. 一句话

**本文件推翻了上一份文档 §5 的核心结论。** `LearningCourse` 的网页形式
`/school/detail/<id>` 实测**恒死**(落 `/error/404`);
上一份文档记的"200 可点"是**只看首跳状态码**得出的假阳性——那 200 来自
`/error/404` 页本身。

**额外类型的可用链接形式,目前一个都没有确认。** 能确认的只有**接口端点**活着,
而接口端点不是给读者点的网页。

## 1. 决定性对照实验:`/school/detail/<id>` 是死的

按本仓纪律(多轮次重复 + 各形式对照),用 3 个真实课程 id × 4 种形式 × 2 轮:

| 形式 | cid=6898 | cid=6896 | cid=200641239941605888 |
|---|---|---|---|
| `/school/detail/<id>` | 200 → **`/error/404?lang=en-US`** | 同 | 同 |
| `/school/course/<id>` | 200 → **`/error/404`** | 同 | 同 |
| `/schoolapi/rest/course/<id>` | 200 原地 | 200 原地 | 200 原地 |
| `/schoolapi/course/<id>` | **404** | 同 | 同 |

**每格均复跑 2 轮,结果逐次相同**,排除限流窗口。

核心事实:两个网页形式**首跳状态码恰为 200**,而 `url_effective` 是
`/error/404`。这正是本仓已记录的**陷阱 1**:"只看首跳状态码 → 会把失效判成可点"。
上一份文档 §5 写"`/school/detail/<id>` **200 可点**",踩的就是这个坑。

补测 8 种候选网页形式(`/school/courseDetail/`、`/course/detail/`、`/school/video/`、
`/school/learnCourse/`、`/school/course/<id>/` 等),**全部 DEAD**(清一色落 `/error/404`);
`/schoolapi/rest/courses/<id>` 与 `/schoolapi/rest/courseDetail/<id>` 是 **404**。

## 2. 课程接口端点确实可用(但它不是网页)

```
GET /schoolapi/rest/course/6898   → code=200, data 含 129 键
```

伪 id 对照(判活不能只看状态码,**要看业务 code**):

| id | 结果 |
|---|---|
| `6898` | code=200,`data.title` = 「星空医药GSP培训课程--存储与养护」 |
| `513283988409192192` | code=200,`data.title` = 「在线学习课程-财务、供应链+合并报表」 |
| `1` | code=200,`data.title` = 「存货核算-管理会计」(说明小整数 id 有效) |
| `999999999` | **`errorCode: 404`,无 `data`** |

正文可用性:三条样本的 `data.subtitle`(逐字稿)长度分别 3135 / 6542 / 17935 字符。
即**课程内容确实拿得到**——但走的是**接口**,不是网页。

## 3. `LearningCourse` 的 id 形状与 `xId`(新事实)

课程条目的 id 有两种形状,同一次响应内混排:

| id 形状 | 样本 | 说明 |
|---|---|---|
| **小整数** | `6898` / `6896` / `6897` / `6899` | 早期课程,`id == coursesId` |
| 雪花 id | `200641239941605888` / `513283988409192192` | 与其余实体同形 |

两条附加事实:
- 上游另给 `xId` 字段,形如 `"LearningCourse-6898"`(**带类型前缀的复合 id**);
- 另有 `resourceType`(`video` / `document` / `ppt`),与 `_norm_item` 现有分支无关。

⚠️ 这解释了为什么**不能**沿用"id 是雪花字符串"的既有假设:课程 id 可能是 `"6898"`
这种短数字串。任何按长度或字符集判形状的写法都会在这里翻车。

## 4. `LearningPath`:仍未确认(与上一份文档一致)

两次采样(`视频教程` / `学习路径` 等 14 词)只捞到 1 条,且它在后续采样中
以 `KnowledgeSpecial` 形态出现(`xId: KnowledgeSpecial-89671503205217280`)。
**独立形态的 `LearningPath` 本轮未稳定复现**,故其可点形式**仍未确认**——保持上一份
文档的判定,不据此给链接。

## 5. `KnowledgeSpecial`:链接形式**不稳定可点**,不成立为政策依据

4 条样本 × 2 形式 × 2 轮:

| id | `/knowledge/specialDetail/<id>` | `/knowledge/special/<id>` |
|---|---|---|
| `872170155949319936` | **ALIVE**(原 URL 留住) | DEAD |
| `89671503205217280` | DEAD | DEAD |
| `568347001339667456` | DEAD | DEAD |
| `352491453127123200` | DEAD | DEAD |

那个唯一的 ALIVE 做了**排除限流窗口**的严格复验:与一个恒 DEAD 的样本**交替测 6 轮**
(每轮间隔 1.05 s),ALIVE 那个 **6/6 全活且最终 URL 原地不变**,DEAD 的 6/6 全死;
换一个时刻再测 3 次,**仍 3/3 全活**。故这是**路径对 id 敏感**,不是限流假阳性。

**判定:`/knowledge/specialDetail/<id>` 对部分 id 可点、对部分 id 不可点。**
这是一个**依 id 而异的**结果,不是"路径可点/不可点"的常量——与本仓
`linkPolicy` 的既有形状(按 kind 一刀切)不兼容。故**不足以支撑给链接**。

## 6. `LearningBroadcast`:已复现,`url` 是**第三方域**

用 `公开课直播` 一词复现(此前 12 词未重现):

```
entity-type : LearningBroadcast
id          : 797227405852501248
xId         : LearningBroadcast-797227405852501248
url         : http://live.vhall.com/542261023     ← 第三方域,非 vip.kingdee.com
liveStatus  : 3    startTime: 2026-01-30 00:00:00   endTime: 2026-01-30 23:59:59
```

该 `url` 的**最终**可点性:

```
http://live.vhall.com/542261023 → 200, 最终 URL https://live.vhall.com/v3/lives/watch/542261023
```

即第三方域**可点**,但它与 `vip.kingdee.com` 的 `linkPolicy` 不是一回事:
本政策的四份文档与全部实测都建立在 vip 域上。**给第三方域的链接需要单独裁定**,
不能套用 vip 域政策(这也是上一份文档 §6 提出的待定项)。

## 7. 结论汇总(实施依据)

| 类型 | 网页链接形式 | 判定 | 接口端点 |
|---|---|---|---|
| `LearningCourse` | `/school/detail/<id>` | **死**(推翻旧结论) | ✅ `/schoolapi/rest/course/<id>`,含逐字稿 |
| `LearningCourse` | `/school/course/`、`/course/detail/` 等 8 种 | **死** | — |
| `LearningPath` | 未确认 | **未确认** | ❌ 未找到 |
| `KnowledgeSpecial` | `/knowledge/specialDetail/<id>` | **依 id 而异**(1 活 3 死) | 未测 |
| `LearningBroadcast` | 上游自带 `url` → `live.vhall.com` | **第三方域,可点** | 未测 |

**对 `other` 档的直接后果**:

1. `other` 档**不能给网页链接**——直到某个类型的网页形式被多轮次确认为活的为止。
   按 `linkPolicy` 的保守方向(少给一个链接,不误导读者),落 `no-link`。
2. 但这与"收进来"不矛盾:**收进来是为了不再静默丢弃**(`total` 与 `results` 对不上、
   `routeErrors` 为空是当前最严重的缺陷)。条目的 `title` 有值(如课程样本
   `highlight.title` = 「星空医药GSP培训课程--存储与养护」),调用方至少知道**存在这类资料**。
3. 课程的正文**经接口可读**——若将来做 `read` 支持,端点已确认可用且含逐字稿;
   这属另一档工作,不在本轮。

## 8. 判活方法留证(第五次)

本文件再次证实:**首跳状态码在两个方向都会骗人**。
`/school/detail/<id>` 与 `/error/404` 页**都返回 200**——只看状态码必然判成可点。
`url_effective` 是本仓唯一可用的判据。

另:本文件 §5 说明**单次观测仍会骗人**——若不交替复验就下结论,那个 ALIVE 会被
读成"路径可点"(实际是依 id 而异)。判定纪律"多轮次重复 + 各形式对照"在本轮再次生效。
