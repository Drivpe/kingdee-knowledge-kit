> 实测日期：2026-09-17 会话 | 全部结论均来自本轮**亲手执行**的命令输出，非推断。

| 问题 | 结论 | 证据 |

## 正文结构实测

请求 `https://vip.kingdee.com/knowledgeapi/knowledge/646787188905978624`（《金蝶AIOpenAPI错误码说明》）的原始输出：

- 顶层键含 `content` / `contentType` / `title` / `attachments` / `classifies` / `products` 等
- `contentType` = `1`
- `content` 长度 **24397** 字符，是 **HTML**（不是 Markdown——实测 `](` 出现次数为 **0**）
- `content` 内 `<img` 标签共 **5 个**（`re.finditer(r'<img[^>]*>')` 精确计数）

### 5 个 `<img>` 标签原文（全量）

```html
<img src="https://vip.kingdee.com/download/010934fa8b105514404d8ebb449d141f0a39.png">
<img src="/download/01095738710f913845ffa0e002d566a772b7.png">
<img src="/download/01091a562c1206f74cf2ad373c6d9585daff.png">
<img src="https://vip.kingdee.com/download/01090e2f0c805ca341f7ae6ac20714be7655.png">
<img src="https://vip-admin.kingdee.com/download/01097bcbe88799fc46bab3ca92c729687ec3.png">
```

**抽取时必须处理的两个形态差异**：

1. **相对路径与绝对路径并存**：第 2、3 张是 `/download/...`，需补 `https://vip.kingdee.com` 前缀。
2. **两个域名**：第 5 张在 `vip-admin.kingdee.com`（不是 `vip.kingdee.com`）。抽取器不能假设单一域名，否则漏图。

⚠️ 注意 `"<img"` 的**字符串计数**会得到 10 而非 5（因为每个标签同时被 `s.count` 与序列化路径重复计入）。**必须用 `re.finditer` 按标签匹配**，不要用 `count`。

### `attachments` 字段

实测值为 **空数组 `[]`**。图片**不在** `attachments` 里，只在 `content` 的 HTML 内联。任何"从 attachments 取图"的方案在本接口上无效。

## 下载链路实测

两种域名的图各自测试（`curl -sL` 跟随重定向，`-A "Mozilla/5.0"`）：

**① `vip.kingdee.com` 的图**

```
起始: https://vip.kingdee.com/download/010934fa8b105514404d8ebb449d141f0a39.png
→ HTTP 302
最终: https://cdn-vip.kingdee.com/ContentImg/2024-04/2024-04-15/34fa8b105514404d8ebb449d141f0a39.png
→ HTTP 200, content-type: image/png, size: 198403
```

**② `vip-admin.kingdee.com` 的图**

```
起始: https://vip-admin.kingdee.com/download/01097bcbe88799fc46bab3ca92c729687ec3.png
→ HTTP 302
最终: https://cdn-vip.kingdee.com/ContentImg/2023-07/2023-07-31/7bcbe88799fc46bab3ca92c729687ec3.png
→ HTTP 200, content-type: image/png, size: 126238
```

**关键事实**：
- 两个域名都重定向到 **`cdn-vip.kingdee.com/ContentImg/<年-月>/<年-月-日>/<hash>.png`**
- **无需 Cookie、无需登录态、无需 Referer**——`curl -sL -A "Mozilla/5.0"` 裸请求即得真图
- 相对路径的图同样可下（实测 `/download/01095738710f913845ffa0e002d566a772b7.png` 补前缀后下载成功，195948 字节，PNG 签名校验通过）

### 图片尺寸实测（影响后续处理）

下载后用 `file` 校验：

```
t1.png: PNG image data, 3268 x 662, 8-bit/color RGBA, non-interlaced
t2.png: PNG image data, 1444 x 1196, 8-bit/color RGBA, non-interlaced
```

⚠️ **`3268 x 662` 是超宽横图**（典型的"界面操作路径"长条截图）。这个尺寸直接命中 `read_image` 的 `maxImageDimension` 限制风险——见下节。

全部为 **8-bit RGBA PNG**，非交错。

## 模型侧约束（本轮最重要的否定性实证）

**实测命令**：对一张自造的 1×1 合法 PNG 调用 `read_image` 工具。

**实测结果**：

```
Error: cannot read "/tmp/imgtest/probe.png" as an image:
model "deepseek-v4.1-flash" does not declare image input;
switch to an image-capable model to read images
```

**根因（已从源码确认）**：DSH 的 `read_image` 工具（实现位于 `@deepseek-ai/dsh-tool-fs`）执行时调用 `assertImageCapableRoute()`，该函数：

1. 解析**当前会话路由**的 provider + model（`requestHeader().config` 优先，回退 `agent.options`）
2. 调 `llm.resolveModelInfo(provider, model)` 取模型信息
3. **要求 `inputModalities` 显式包含 `"image"`**，否则抛错拒绝

`inputModalities` 来自**模型目录（catalog）声明**；未声明时默认为 `["text"]`（源码：`inputModalities: model.inputModalities ?? ["text"]`）。

**推论**：
- 这是**逐路由（per-route）判定**，不是 harness 全局能力开关——换一个声明了 image 的模型即可能通过。
- 当前会话跑在 `buddy` provider 的 `deepseek-v4.1-flash` 上，该路由**未声明 image 输入**。
- 所以「把图片带进回答」与「Agent 读懂图片内容据图作答」这两件事，在**当前路由下均不成立**；不取决于金蝶侧，而取决于所选模型。

**未验证**（诚实标注）：本机 `buddy` provider 的模型目录里是否**存在**任一声明 `image` 的模型，本轮未逐项枚举确认。

**但有解**——本机已装一个**绕开门控的侧路工具**，见下节。

## 决定性发现：`describe_image` 侧路（绕开模型门控）

本机 `~/.dsh/profiles/web/node_modules/@linxin666/dsh-tool-describe-image`（v0.3.23）已存在。其 `package.json` 自述原话：

> "gives a **text-only model image understanding** by asking a vision-language model at an OpenAI-compatible endpoint to describe one image (local path, **http(s) URL**, or attachment reference)"

**这正好解决「Agent 读懂图片内容据图作答」的需求，且不依赖当前模型是否有视觉能力。**

### 它怎么工作

- 工具名 `describe_image`，参数两个：`image`（本地绝对路径 / **http(s) URL** / attachment 引用）和 `prompt`（**显式指令**，如 "transcribe all text"、"extract the table as CSV"、"diagnose the UI problems"）
- **图像本身不进对话上下文**——工具只返回视觉模型的**文本**结果（源码注释：`The image never enters the conversation: the tool returns only the vision model's text answer`）
- 支持多个 endpoint 轮换（`rotationMode: round-robin`）、语义缓存（同图同 prompt 短时复用）、失败降级
- 支持路径：本地文件、**http(s) URL**、attachment 引用、Markdown 图片引用

### 当前状态：未配置、未挂载

- 挂载方式：`dsh plugin --profile web add link:<repo>/packages/dsh-tool-describe-image`（配置文件 `cordis.patch.yml`）
- **需要先配一个 vision endpoint**（OpenAI 兼容的 `baseURL` + `model` + `apiKey`）；未配置时首次调用报 "unconfigured"
- 本会话的工具清单里**没有** `describe_image`，证明当前未启用

### 对金蝶图片的适配性

**极佳**。因为该工具直接吃 `http(s) URL`，而金蝶配图经我们实测是**可匿名访问的 CDN URL**——`https://cdn-vip.kingdee.com/ContentImg/...`。所以链路可以简化为：

```
kd read <id> → content HTML → 正则抽 <img src>
  → 归一化为绝对 URL（含双域名处理）
  → describe_image(image=URL, prompt="转录图中所有文字并说明操作路径")
  → 文本结果并入回答
```

**完全不需要先下载图片到本地**，也不受 `read_image` 的模型门控限制。

## CDN 防盗链实测：零防护

模拟 VLM endpoint 取图的三种情形（`cdn-vip.kingdee.com` 的原始图 URL）：

| 情形 | 结果 |
|---|---|
| 无 Referer | `HTTP 200`, `image/png`, `198403` 字节 |
| **伪造 Referer**（`https://evil.example.com/`） | `HTTP 200`, `image/png`, `198403` 字节 |
| **空 User-Agent** | `HTTP 200`, `image/png`, `198403` 字节 |

**结论：`cdn-vip.kingdee.com` 不校验 Referer、不校验 UA。** 任何 VLM endpoint 都能直接以 URL 拉取，无需代理、无需注入 Header。

**至此图片链路逐环实证完毕，无未知环节**：
`kd read` HTML → 抽 `<img>` → 归一化 URL → 传给 `describe_image` → 文本结果 → 并入回答。

唯一的配置前置是**有一个可用的 vision endpoint**。

## 对 `kd` 侧的实现建议（若要做图片能力）

**取图这一步零障碍**：`kd read` 拿到 `contentText` 后，正则抽 `<img src=...>` → 归一化为绝对 URL → `urllib` 下载到本地目录。纯标准库可完成，符合仓库「零外部依赖」纪律。

**必须处理的三件事**（否则会漏图或误判）：
1. 相对路径补前缀（`/download/...` → `https://vip.kingdee.com/download/...`）
2. 双域名（`vip.kingdee.com` + `vip-admin.kingdee.com`）都要接受
3. 用 `re.finditer` 按标签匹配，**不要用 `str.count("<img")`**

**需要留意的约束**：
- 图是**超宽横图**（实测 3268px 宽），若要走 `read_image` 需先降采样到限制以内
- `content` 是 HTML，图与正文的**位置关系**（图在哪段文字之后）是有效信息——抽图时保留偏移量，可用于"据图作答"时的上下文对齐
- 下载目标建议落独立目录（如 `~/.lingeebuild/images/<knowledgeId>/`），与 `kd` 不落盘的既有纪律区分开——**图片是持久资产，与检索缓存性质不同**

## 实测命令留档（可复现）

```bash
# 抽图（不含下载）
python3 -c "
import json,urllib.request,re
url='https://vip.kingdee.com/knowledgeapi/knowledge/646787188905978624'
req=urllib.request.Request(url, headers={'User-Agent':'Mozilla/5.0'})
d=json.loads(urllib.request.urlopen(req, timeout=25).read().decode('utf-8','replace'))
for i,m in enumerate(re.finditer(r'<img[^>]*>', d.get('content') or ''),1):
    print(i, m.group(0))
"

# 下载并验证（跟随重定向）
curl -sL -A "Mozilla/5.0" --max-time 25 \
  -o t1.png "https://vip.kingdee.com/download/010934fa8b105514404d8ebb449d141f0a39.png"
file t1.png
```
