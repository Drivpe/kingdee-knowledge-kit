## 问题

模块 docstring 声称"唯一网络出口",但实际有**两个独立入口**,而没有任何单一注入点能拦住全部请求:

```
up._get_json  is net._get_json -> True      # 导入期快照,替换 net 的无效
det._get_json is net._get_json -> True      # 同上
替换 net._get_json → 未被拦住(真请求成功)
替换 up._get_json  → 被拦住(BLOCKED)
```

`_net._RATE is cfg._RATE -> True` —— **限速器同样是快照**。

**决定性实测**:用 `sitecustomize.py` 钩住 `urllib.request.urlopen`,跑完整 48 条离线用例:

```
通过 48 / 失败 0
=== 期间漏出到真实上游的请求 ===
URLOPEN https://vip.kingdee.com/api/search?text=信用额度控制...
```

**漏出 1 次,48/48 全绿。** 承重点是装机自检 `install.sh:150` / `install.ps1:207`
—— **跑在用户机器上,并且会真发一次请求**。有网就发,没网就静默吞进 `routeErrors`
(把代理指向死端口 `127.0.0.1:1` 时 48/48 照样通过)。

## 要建的

让"替换 `_net._get_json` 就拦住全部上游请求"成为**真的**,并让离线测试组真的不联网。

改法:两处 `from ._net import _get_json` 的导入期快照改为**模块属性访问**。
`_manifest` 已经是属性访问,不动。

```python
# 现状(快照)
from ._net import _get_json
# 改为(属性访问)
from . import _net
... _net._get_json(url, rate)
```

限速器快照与网络出口**同批**处理,否则"拦住网络但拦不住限速"会让并发改造的测试失去控制手段。
