## 问题

交互链路的红线数字只有一个,就是 `contract.json` 的 `limits.rate.interactive`
(`{burst: 3, rps: 2.5, jitterMs: [40, 220]}`)。它需要上调,而**当前没有任何用例引用
它的具体数值**——现有回归只断言档名 `_rate_profile() == "interactive"`。

**这正是它当初变成"匿名常量"的原因**:改数字不触及测试,于是没人知道它被改过。
README 一度声明了约束却不写数字,`CONTEXT.md` 契约声明条点名批评过这种"名实不符"。

## 要建的

### 1. 数值上调

`contract.json` 的 `limits.rate.interactive`:`{burst: 3, rps: 2.5}` → `{burst: 7, rps: 5}`。
`jitterMs` **不动**。

依据:

- `burst` 对齐"单次操作最大请求数"——`maxKeywords = 7` 是单次 `search` 的路数上限。
  此前 `burst = 3` 意味着 7 路搜索必须排两次队,而排队那 1.6 秒**零安全价值**
  (实测上游在 7 路并发下无任何限流信号)。
- `rps` 翻倍仍在"人类手动操作密度"内:用户是唯一人工触发者,每次 `kd search` 是一次明确动作。
- **放宽只对 ≥4 路生效,3 路及以下行为完全不变**(`delay` 恒为 0)。

### 2. 钉住新数值的用例

新增一条**引用具体数值**的用例(不是只断言档名)。
