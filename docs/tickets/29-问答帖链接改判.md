## 问题

**问答帖链接是可点的,失效的不是"问答这一档",是 URL 形式。**

| 形式 | 实测 |
|---|---|
| `/questions/<帖子号>/answers/<回答号>`(正确) | **22/22 可点** |
| `/question/<帖子号>`(内核现用,单数) | **22/22 不可点** |
| `/questions/<帖子号>`(复数,无 aid 段) | **4/4 不可点** |

内核拼的是**中间那个**,故 `linkPolicy` 对 `question` 落 `no-link`,整档**当前不给链接**。
该政策建立在"问答恒不可点"的结论上,**那个结论现在被推翻**。

页面内容已核实(不只是状态码):长形式页面 `<title>` 与上游 `question.title` **逐字一致**,
正文含帖子标题与采纳回答原文。回答号**必须精确**(`+1`、`1`、`0` 均落 `/error/404`)。

## 要建的

### 1. 清单条目补回答号

回答号来源:`_upstream._norm_item` 的 answer 分支**原本就拿得到**(`x["id"]`,当前被丢弃)。

```python
# 路一:从 search 的 answer 条目直接取(原始 JSON 里两个 id 都在)
#   x["questionId"] → 帖子号
#   x["id"]         → 回答号  ← 内核当前只取前者,这个被丢弃
```

**帖级合并时的取舍**:采纳回答优先(`isAdopt`),无采纳回落上游首条。

⚠️ 上游 `id` 字段被复用作**帖子号**(决策 D6),而回答号也在上游的同名 `id` 上——
实现时须避免两者混淆。清单 `id` 仍必须是**帖子号**(帖子级,ADR-0014)。

### 2. URL 模板改为长形式

`_URL_OF["question"]` 由 `/question/%s` 改为
`/questions/<帖子号>/answers/<回答号>`。
**回答号缺失时不得拼出短形式**(短形式 22/22 死)——须落到"不给链接",而不是给个死链。

### 3. `linkPolicy.question` 由 `no-link` 改 `link`

**必须与 1、2 同批做**,否则是"政策允许但内核给不出链接"的空承诺。

### 4. 修正 `contract.json` 的 forbidden 备注

现写:「不要把 `question/` 改写成 `questions/`(复数)——实测该路径同样不存在(15/15 全 302)」。

**该备注仍有效但理由错了**:复数路径并非"不存在",而是**必须带 `answers/<aid>` 段**。

| 形式 | 判定 | 真实原因 |
|---|---|---|
| `/question/<qid>`(单数) | 死 | 该路径整体不存在 |
| `/questions/<qid>`(复数、无 aid) | 死 | 路径存在但**缺必需的回答号段** |
| `/questions/<qid>/answers/<aid>`(复数、带 aid) | **活** | 正确形式 |

### 5. 文档面同步

`linkPolicy.question` 的改判会牵动四份文档的链接口径,须一并同步
(离线回归有 `t_link_policy_docs_in_sync` 钉子会抓)。
