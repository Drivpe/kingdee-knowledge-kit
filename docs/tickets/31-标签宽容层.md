## 问题

`_manifest._norm` 只做 ASCII `.lower()`,`_upstream._norm_item` 内部**零归一**、
直接字面量比较:

| 输入值 | `_norm_item` | `_manifest._norm` |
|---|---|---|
| `'Knowledge'` / `'knowledge'` / `'KNOWLEDGE'` | OK | OK |
| `'  Knowledge  '` | **None(丢弃)** | **None(丢弃)** |
| `'Knowledge\n'` | **None(丢弃)** | **None(丢弃)** |
| `'Ｋｎｏｗｌｅｄｇｅ'`(全角) | **None(丢弃)** | **None(丢弃)** |

**关键脆弱点**:`_norm_item` 的形参契约写着「`et` 是上游的 `entity-type`(**已小写**)」
—— **完全依赖唯一调用方遵守,函数内部无任何防御**。把 `_manifest` 的 `.lower()` 去掉,
`_norm_item` 会退化为大小写敏感、**全量静默丢弃** —— 而 48 条离线用例**测不出来**
(直调 `_norm_item` 的用例自己传小写,绕过了 `_norm` 这一层)。

两份归一不是重复实现,而是**互补但分层脆弱**:一个什么都不做,一个只做 `.lower()`。
`strip()`、NBSP、全角折叠(NFKC)、尾换行**三层都不管**。

## 要建的

在归一入口加**宽容层**:`strip` + `lower`,容忍前后空白 / 尾换行 / 全角 / NBSP。

同时:**`_norm_item` 不得再假设入参"已小写"** —— 要么在函数内自己归一,
要么把形参契约改写清楚并留一条防御。当前"契约靠调用方遵守、函数零防御"的形态
本身就是缺陷的一部分。
