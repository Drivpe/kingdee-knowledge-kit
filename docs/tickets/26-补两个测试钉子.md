## 问题

工单 #24 的修复(`read` 遇上游 404 时不再误报"text 超 100 字符")靠调用点**手写一行**
`op="read"`(cli.py:125)——**删掉它,48 条离线用例全绿**。

变异测试复现:

```
原版    $ kd read 123456789012345678 → hint = 按 id 取全文时上游报错…
变异版  $ kd read 123456789012345678 → hint = 上游以 HTTP 200 返回错误壳
                                          (常见于检索词超 100 字符…)     ← search 语境
```

**为什么测试抓不住**:零测试断言 `read` 错误体的 `hint` / `example`。

## 要建的

两条钉子,把两个"没有守护的措辞"钉住。

### 钉子一:`cli._guard` 的 `op`

**要点(已双版本验证:原版 PASS、变异版 FAIL)**:

- 必须走 `cli.main(["read", ...])` **真调用路径** —— 直接调 `_guard(op="read")`
  在 `op` 被删后**仍会通过**,测不到回归;
- 必须打桩 `cli._out`,**不能**用 `redirect_stdout` —— 后者内部调
  `sys.stdout.reconfigure`,而 `io.StringIO` 没有该方法。

### 钉子二:ANSWER-SPEC 措辞

文档口径目前没有回归守护,同批补一条。

## 验收标准

- [ ] `read` 错误体的 `hint` / `example` 有断言,且断言的是 **read 语境**的措辞
- [ ] **变异测试验证**:删掉调用点的 `op="read"` → 该用例**必须红**(不是看着绿就行)
- [ ] 打桩用 `cli._out` 而非 `redirect_stdout`(后者会因 `StringIO` 缺 `reconfigure` 而炸)
- [ ] ANSWER-SPEC 措辞钉子落地,且**变异验证**它能抓到措辞漂移
- [ ] 离线回归 48/48 保持绿(新增用例计入)
