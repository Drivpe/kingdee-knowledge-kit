# ADR-0018:K1 链接单点化 —— 条目对外链接只有一个归属地

ADR-0014(清单粒度改帖子级,决策 D6 两个 id 空间)、ADR-0016(检索词生成权移交)、
ADR-0017(问答链接改判长形式可点) | 承接:2026-10-01 K1 施工
(`.scratch/批次A-K1-施工报告-20261001.md`)+ 2026-10-03 接手核对与终审复核

## 背景

2026-09-29 的链接改判(ADR-0017)确认问答的可点形式必须带回答号:
`/questions/<帖子号>/answers/<回答号>`。改判之前,链接构造分散在**两处**:

| 位置 | 它知道什么 |
|---|---|
| `_upstream._URL_OF` + `_upstream._question_url` | 页面 URL 模板、必需段规则、"回答号已知时怎么拼" |
| `_detail._question_detail` | 问答 url 按 `bestAnswer[0]` **单点**取回答号 |
| `_manifest_merge` 的帖级回落链 | 同一件事的**第二次推导**:"采纳优先 → 上游首条" |

「该取哪个回答号」被推导了两遍,后果**实测复现**:同一个帖子、两条**都未被采纳**的
回答(A1/A2)时,`search` 侧经帖级回落链给出 `…/questions/<qid>/answers/A1`,
而 `read` 侧按 `bestAnswer[0]` 给出 `None`(无采纳即"取不到")。

这条分叉落在一个具体的调用纪律上:ANSWER-SPEC 让 agent **照抄 `url` 字段**。
于是同一个帖子,列清单时给得出链接、写正文时又给不出 —— 读者以为资料不存在。

## 决策

### 决策 1:链接规则收进 `_links.py`,单一归属地

`src/kd/_impl/_links.py` 是"链接长什么样"的**唯一**归属地,分三档,分工不得混:

| 层 | 职责 | 关键约束 |
|---|---|---|
| `compose_url(kind, item_id, answers)` | **数据形状层** —— 如实指向上游内容页 | **不含**政策闸门 |
| `link_for_item(kind, item_id, answers)` | **读者拿到的形态** = `compose_url` + `apply_link_policy` | 政策闸门住这里,故 `read` 侧调用点**不可能**忘加 |
| `_pick_answer_id(answer_ids)` | 回答号选取(零算法契约) | 单一实现,两侧共用 |

清单路径(`_manifest_project`)**仍是它那条通路的唯一闸门** ——
`_upstream._norm_item` 各处经 `compose_url` 如实拼 url、**不加**闸门,
再由 `_manifest_project` 按政策抑制。在那里也加闸门即变成**两个闸门**,
政策就"有两处生效点",单一来源即失效。

**判据(回归钉子)**:页面形式的 URL 模板(`VIP + "/…"` 里不带 `/api/` 的)
只允许出现在 `_links.py` 一处,由 `t_link_single_source_same_url` 的 ④ 段按
**剥注释、保留字符串**的方式扫描源码钉住(用 `code_only` 会连字符串一起剥掉而恒绿)。

### 决策 2:回答号选取 = 零算法契约 +**一处已裁定的放宽**

`_pick_answer_id` 的基准规则照抄 `_manifest_merge` 原先那条帖级回落链:
采纳优先 → 上游首条 → 否则 `None`。内核不排序、不打分、不猜"哪条更像解"。

⚠️ **但这不是"逐字等于"**,如实声明一处放宽:本函数先对每个候选做 `_s()` 归一
(等价于原 `_question_url` 的 `str(...).strip()`),**再**丢弃空段 —— 于是"空白段"
被视为**该段缺失**而跳过,落到下一个非空候选。HEAD 的帖级回落链用真值过滤
(`"   "` 为真 ⇒ 不跳过)。实测两版对照:

| 构造 `answer_ids` | HEAD 版回落链 | 现版 |
|---|---|---|
| `[("   ",False),("11",False)]` | `None` | `"11"` |
| `[("   ",False)]` | `None` | `None` |
| `[("11",False),("12",False)]` | `"11"` | `"11"` |

**性质**:真实上游的回答号恒为**无空白的数字串** ⇒ **生产不可达**。
这是**契约/实现不符**,不是线上故障,不得写成"线上 bug"。

**口径(2026-10-03 用户裁定"承认放宽")**:保留跳过逻辑,理由是语义上
"跨过缺段找一个可用回答号"优于"整帖给不出链接",且方向与 `compose_url` 的必需段
规则一致(宁可归一、宁可跳过,也不把含空格的死链交给读者)。

**判据**:`t_pick_answer_id_multi_candidate_blank_skip` —— **多候选**构造,
去掉 `if not aid: continue`(保留 `_s()`)必须红。既有的 ⑤ 钉子只覆盖**单候选**
空白,那一档在单候选下判不出差异(实测:该变异在补钉子前**全套件仍全绿**)。

### 决策 3:删掉死的具名函数 `_question_url`,不补假消费者

`_question_url(qid, aid)` 重构后**零生产读点、零回归读点**,只剩 `_impl/__init__`
的再导出在撑一个名字。处置与判例 `_URL_OF["other"]` 一致:**删键**,不补假消费者
(那次有哨兵实验留证:该键在生产路径**从不被读**)。

"回答号已知"的场景现在的正确写法就是单元素候选集:

```python
compose_url("question", 帖子号, [(回答号, None)])   # 单元素候选集
```

**判据**:`t_question_url_never_substitutes_item_id` 的 ④ 段断言
`not hasattr(cp, "_question_url")` —— 该名字若回来,就是"另开一条拼 url 的路"。

### 决策 4:候选集必须显式给,**不得**拿 `item_id` 顶替回答号

`compose_url("question", 帖子号)` 在缺候选集时曾退化成"回答号 = `item_id`",
拼出 `/questions/<qid>/answers/<qid>` —— 一个**形状合法、实则错误**的链接。

它的危害比短形式**更大**:短形式恒死(读者一点就知道打不开),而这个形态完全合规,
读者会以为"资料就在那里,只是没写清"—— 把"我们给错了"伪装成"上游长这样"。

**判据**:缺候选集 → `None`;空候选集 → `None`;给了候选集 → 用候选里的回答号拼复数长形式,
且不得出现 `answers/<帖子号>`。

## 残留边界(如实记,不假装已消除)

上游搜索**压根没召回该帖的采纳回答**时:清单只知道"这帖有采纳答案"(`adopted` 为真)
却不知道是哪条 → 回落首条;而 `read` 拿得到 `bestAnswer` → **两侧仍可能不同**。

这是**信息可见性**的差异(上游那一轮没把采纳回答返给我们),**不是规则的分叉** ——
规则只有一套,住在一个模块里。处置原则同顶层 `total` 那次:**写清,不假装**
(那个字段本身已于 v6.9 删除;留下的是当时那条处置原则,不是字段)。

## 不做的事

- **不把政策闸门下沉到 `_upstream`**。那会造出第二个生效点,与决策 1 直接冲突。
- **不给 `_URL_OF` 补回 `other` 档的模板**。`other` 恒 `no-link`,那个键是生产死键。
- **不把 `_pick_answer_id` 改成"逐字等于 HEAD 的帖级回落链"**。决策 2 已裁定承认放宽。
- **不让 `_manifest_merge` 与 `_detail` 各自推导回答号**。那是本 ADR 治的原始形态。
