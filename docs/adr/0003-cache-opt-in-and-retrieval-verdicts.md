# ADR-0003:缓存语料库 opt-in;信号重排与同义词变体被评测否决

日期:2026-09-06 | 状态:已采纳 | 关联:交接文档 16、docs/eval-report-v4.md

## 背景

文档 14/15 遗留「答案拟合度优化」。官方 AI(分享样例 clzL8 及 4 组用户对话)展示了 chunk 级召回的效果;v4.0 尝试了查询侧(同义词变体)、排序侧(信号重排)、存储侧(本地缓存语料库)三条路,并以 23 例评测集定案。

## 决策

1. **本地缓存语料库(sqlite+FTS5)采纳,但默认关闭(opt-in)**;用户本机经启动器 `KSEARCH_INDEX=on` 开启。
2. **信号重排保留代码路径、默认关闭**:评测显示手工信号权重(标题/采纳/浏览量/新鲜度)压过上游相关度排序,recall@10 -11%、MRR -6.6%。
3. **同义词变体整块移除**:无召回增益、时延×2、每次检索多打 2 次上游;上游中文分词已足够。用户判断与数据一致。

## 理由(为什么缓存 opt-in 而不是默认开)

- 本套件对匿名分发,默认行为必须零落盘、零状态(部分用户场景敏感);
- 缓存价值与使用频次成正比,重度用户(agent 所在本机)才需要;
- opt-in 同时构成 A/B 开关,评测可随时复现。

## 后果

- 暖读提速 ≈30 倍(427ms→14ms),上游重复调用归零(人类频率红线结构性缓解);
- 缓存召回完全透明(评测三项指标逐位一致);
- `chunks` 表预留 embedding BLOB 列:二期向量召回原地升级,零迁移——但必须先过评测集证明增量;
- 教训沉淀:**任何检索侧改动先过 `run_eval.py`,不做无测量的"优化"**(信号重排是反例)。

## 备选与取舍

- faiss/chromadb 作向量库:依赖重,对本套件体量(1-10 万 chunk)过度设计,弃;
- 手工信号重排+更强位置先验:可再调参,但本次评测已证伪当前权重,不值默认位;
- 云端 embedding API:触碰零账号红线,弃。

## 增补(2026-09-06,评测口径正式化)

**评测金标双层化,正式使用脱离官方 AI 对话**:usage 层(真实使用的问题,gold=解题文档,先标金后测管线)是唯一达标口径(12 例,recall@5=0.756/MRR=0.628);官方对话金标降为 reference 层仅作参考(14 例,recall@5=0.120——其语义索引含匿名检索不可达文档,不构成对匿名管线的公平口径,且生产不应依赖官方 AI 的行为样本)。理由:①官方分享链供给不可控;②真实使用才是服务质量的本义;③usage 金标有自证循环风险,以「金标在管线改动前定死」对冲。
