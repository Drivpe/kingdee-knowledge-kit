# ADR-0010:召回置信度用三档枚举,不用数值分数

日期:2026-09-16 | 状态:已采纳 | 关联:ADR-0008(合成权移交调用方)、docs/ANSWER-SPEC.md

## 背景

系统当前**没有任何"第一轮失败"判定**——不管检索到什么都直接进回答。用户拍板:
让合成方 LLM 自行判断召回是否准确,置信度不够就坦诚告知。

这引出两个必须一次定死的实现问题:判定结果用什么形态表达?判定方能看到什么信号?

## 决策

### 1. 三档枚举,禁止数值分数

档位用**可操作的语义**描述,不用抽象等级(高/中/低),以把判断锚在有证据的观察上:

| 档位 | 判据 |
|---|---|
| `answerable` | 召回文档中有段落直接说明了机制/字段/步骤 |
| `partial` | 有相关材料,但未覆盖用户问的那个点 |
| `uncovered` | 召回内容与问题不匹配,或检索本身未命中 |

**禁止让 LLM 输出 0-1 分数。** 理由:

- **无校准。** LLM 未受训做输出概率的校准——它给的 0.8 里并非真有 80% 正确。
  同一件事换问法可得 0.5 或 0.9,该数字是**看起来精确的噪声**,信息量低于"不确定"三字。
- **量纲冲突。** 客观信号已存在(`fusedScore` 真实上游排序分、命中路数、`budget_exhausted`)。
  LLM 凭空给的 0.75 与它们不在同一量纲,无法融合,反而污染判断。若确需分数,
  应从客观量计算,不是问模型要。
- **破坏诚实。** 分数诱导中间偏高的取值(训练数据里"确信"表达占多数),
  导致**该说"不确定"时给了 0.7**,读者误以为尚可。分档无模糊空间。

### 2. 判定方必须看到召回信号

仅给正文不足:LLM 只能凭"读起来像不像在回答"猜,那是退化的判断。
须把客观召回信号一并喂入合成上下文:`fusedScore`、命中哪几路、`budget_exhausted`、检索次数。

### 3. 单次调用,JSON 头 + 正文连写

合成方在**同一次调用**中先输出一行 JSON 头(含 `confidence` 与 `basis`),紧接正文。
不做两次调用(先判后写)——判定不受自己刚写的正文影响虽更准,但 LLM 调用翻倍,收益不抵成本。

### 4. 一次判断、两种呈现

结构化字段是**判定真身**,正文自然语言是**给人看的投影**,不是两套独立判断。
`confidence` 为 `uncovered` 时,正文须按 ANSWER-SPEC 第 4 条给出诚实声明。
元数据供 agent 读,自然语言供人读。

## 后果

- **`confidence` 与 `basis` 由合成方输出,不由 kd 输出**(见下方「修订说明」);
  `ANSWER-SPEC` 增置信度声明规则;
- 判定质量取决于合成方模型能力,须以"与人工直觉一致"验收(该说不确定时说了没);
- 无需阈值标定——这是相对阈值判定的核心优势:阈值只能看分数,无法回答
  "这几篇讲的是不是同一个问题"这种语义问题。

## 修订说明(2026-09-16,与 ADR-0008 对齐)

本节记录一条**被本 ADR 原文掩盖的冲突**,以及消解方式。

原文第「后果」节写「**输出体**新增 `confidence` 与 `basis` 字段」,这句在 ADR-0008 之后**已不成立**:
ADR-0008 把合成权移交调用方,`kd` 从此零模型依赖、只产资料包、不合成任何文字。
既然 kd 不合成,它**在结构上就不可能产出**这两个字段——字段描述的是"合成方的判定结果",
而 kd 连判定都不做。

**落点因此拆成两半:**

1. **生产端 = 合成方(调用方 agent / 其子代理)**:`confidence` 与 `basis` 由它在**同一次合成调用**里
   作为 JSON 头输出(决策第 3 条),落点在 `skills/kingdee-knowledge/skills/kingdee-knowledge/SKILL.md`
   的子代理提示词模板「置信度判定(必填)」段——模板里那句
   `{"confidence":"answerable|partial|uncovered","basis":"一句话依据"}` 就是本 ADR 的字段契约。
2. **供给端 = kd**:kd 只提供判定所需的**客观观测信号**,即资料包顶层 `synthesisBrief`
   (`sourceCount` / `topScores` / `routeKinds` / `budgetExhausted` / `upstreamUsed` / `recallHint`),
   实现于 `cli/kd.py` 的 `_synthesis_brief()`。它**只做搬运与去冗,不产生任何判断**——
   这正对应决策第 2 条「判定方必须看到召回信号」。

**不要改回 kd 输出这两个字段**:那会要求 kd 重新持有模型通道,直接推翻 ADR-0008 已经过质询的核心决策。
阅读本 ADR 时,「输出体」一律理解为**合成方的回答输出体**,而非 kd 的 `ask` 返回体。

## 备选与取舍

- **阈值规则触发第二轮检索**:被否——阈值需标定,而评测体系当前已搁置(精度不足),无法标定;
- **连续分 0-1**:被否,理由见上;
- **只在正文里自然语言声明、不加字段**:被否——agent 想读就得再跑一次 LLM 或写中文正则解析,成本更高且易被语气漂移影响。
